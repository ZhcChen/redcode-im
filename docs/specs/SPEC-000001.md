# 技术方案：合并 devflow-core 工作流程架构

## 1. 概述

将 `/Users/chen/code/devflow-core` 中的完整工作流程架构（流程文档、模板、角色职责、技能集）合并到 RedCode IM 仓库，并在 `docs/` 内完成**全量结构迁移**：流程文档归档到标准目录，原有业务文档统一迁移到 `docs/reference/`，形成单一入口与统一格式。

## 2. 需求映射

| PRD 需求 | 设计模块/接口 | 说明 |
|----------|---------------|------|
| 合并 devflow-core 工作流架构 | docs/workflow + docs/templates + docs/conventions | 引入 devflow 标准目录与模板 |
| 合并 devflow-core skills | skills/devflow-* | 以仓库内可追溯方式落盘技能集 |
| 统一文档入口 | docs/index.md | 以 index 作为唯一入口 |
| 迁移原业务文档 | docs/reference/** | API/架构/指南/运维/安全/法律/测试统一归档 |
| 保持可更新与可回滚 | vendor + 记录同步策略 | 当前以 vendor 迁移，保留后续同步方式说明 |

## 3. 约束与假设

- 现有 `docs/` 目录需要整体迁移到新结构。
- 不引入 devflow-core 中的 `.env` 等敏感文件。
- `docs/reports/` 需保持路径不变（Dashboard 依赖）。
- 采用可回滚的合并策略（vendor + 记录同步方式）。

## 4. 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 合并方式 | vendor 复制（当前） | 直接落盘，便于快速完成全量迁移 |
| 文档落点 | docs/（标准目录） | devflow 标准目录作为主结构 |
| 技能落点 | skills/devflow-* | 与 docs 同仓库管理，便于对齐版本 |
| 更新策略 | 复制脚本 / subtree（可选） | 保障后续与 devflow-core 同步能力 |

## 5. 架构设计

### 5.1 文档结构映射

- `devflow-core/docs/` → `redcode-im/docs/`（workflow/templates/conventions/requirements/...）
- 原 `docs/*` 业务文档 → `docs/reference/*`
- `docs/README.md` → `docs/index.md`（统一入口）

### 5.2 技能结构映射

- `devflow-core/skills/devflow-*` → `redcode-im/skills/devflow-*`
- 保留每个 skill 的 `SKILL.md` 与相关脚本
- 排除 `.env` 等本地机密文件（若存在，提供 `.env.example` 或说明）

### 5.3 入口与引用

- `docs/index.md` 作为唯一入口，包含流程与参考文档索引
- `AGENTS.md` 更新入口与文档结构规则
- `docs/reports/` 路径保持不变

## 6. 接口设计

本次合并不涉及 API 接口变更。

## 7. 数据模型

不涉及数据库或数据模型变更。

## 8. 关键逻辑与流程

### 8.1 合并流程（建议）
1. vendor 方式引入 devflow-core docs/skills（排除 `.env`）
2. 迁移原文档到 `docs/reference/`，保持目录语义不变
3. 将 `docs/README.md` 统一为 `docs/index.md`
4. 批量更新文档链接与入口引用
5. 保持 `docs/reports/` 原路径
6. 验证链接与模板可用性（手动检查）

### 8.2 同步流程
- subtree 方案：通过 `git subtree pull` 同步 devflow-core 更新（可选）
- vendor 方案：用脚本复制并记录版本号（当前）

## 9. 非功能目标

- 可追溯性：所有流程文档与模板落盘在仓库内
- 低冲突：保留业务文档内容，结构迁移后统一入口
- 可维护：提供清晰的同步/更新路径

## 10. 安全与风险

- 风险：误提交 devflow-core 的 `.env` 或本地机密
- 规避：迁移时明确排除 `.env`，必要时提供 `.env.example`

## 11. 兼容与版本策略

- 迁移完成后以新结构为唯一入口，旧入口仅保留跳转或说明
- 允许按需在 `docs/reference/` 中新增业务扩展说明

## 12. 回滚与迁移

- 回滚方式：移除新增标准目录与 `skills/devflow-*`，回退 `docs/index.md` 与 `AGENTS.md`
- 不涉及数据库迁移

## 13. 影响范围

- 新增文件：`docs/workflow/**`、`docs/templates/**`、`docs/conventions/**`、`docs/requirements/**`、`docs/development/**`、`docs/reviews/**`、`docs/tests/**`、`docs/backlog/**`、`skills/devflow-*`
- 修改文件：`docs/index.md`、`AGENTS.md`、原文档路径（迁移到 `docs/reference/`）
