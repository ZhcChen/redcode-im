# 技术方案：合并 devflow-core 工作流程架构

## 1. 概述

将 `/Users/chen/code/devflow-core` 中的完整工作流程架构（流程文档、模板、角色职责、技能集）合并到 RedCode IM 仓库，形成可复用且可追溯的研发流程基线，并保持现有业务文档结构不被打断。

## 2. 需求映射

| PRD 需求 | 设计模块/接口 | 说明 |
|----------|---------------|------|
| 合并 devflow-core 工作流架构 | docs/devflow/* | 将 devflow-core 文档放入独立子目录，避免与现有 docs 冲突 |
| 合并 devflow-core skills | skills/devflow-* | 以仓库内可追溯方式落盘技能集，供 Codex/AI 引用 |
| 统一流程入口与 AGENTS 规则 | AGENTS.md + docs/README.md | 明确流程入口与确认节点规范 |
| 保持可更新与可回滚 | Git subtree / vendor 方案 | 支持后续更新 devflow-core 版本 |

## 3. 约束与假设

- 现有 `docs/` 目录结构不迁移、不重排，仅新增 devflow 专属子目录。
- 不引入 devflow-core 中的 `.env` 等敏感文件。
- 允许新增 `docs/specs/` 等流程类目录，但不强制迁移已有文档。
- 采用可回滚的合并策略（subtree 或 vendor）。

## 4. 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 合并方式 | Git subtree（推荐） | 不引入 submodule 复杂度，便于在单仓库内维护与更新 |
| 文档落点 | docs/devflow/ | 与现有 docs 并行，降低冲突风险 |
| 技能落点 | skills/devflow-* | 与 docs 同仓库管理，便于对齐版本 |
| 更新策略 | subtree pull / 复制脚本 | 保障后续与 devflow-core 同步能力 |

## 5. 架构设计

### 5.1 文档结构映射

- `devflow-core/docs/` → `redcode-im/docs/devflow/`
- `devflow-core/docs/index.md` → `redcode-im/docs/devflow/index.md`
- `devflow-core/docs/*` 原结构保持不变，仅调整内部相对路径

### 5.2 技能结构映射

- `devflow-core/skills/devflow-*` → `redcode-im/skills/devflow-*`
- 保留每个 skill 的 `SKILL.md` 与相关脚本
- 排除 `.env` 等本地机密文件（若存在，提供 `.env.example` 或说明）

### 5.3 入口与引用

- `docs/README.md` 增加“开发流程（devflow）”入口
- `AGENTS.md` 增补流程规范指向 `docs/devflow/workflow/`
- 现有规则保留，不覆盖本仓库特有约束

## 6. 接口设计

本次合并不涉及 API 接口变更。

## 7. 数据模型

不涉及数据库或数据模型变更。

## 8. 关键逻辑与流程

### 8.1 合并流程（建议）
1. 引入 devflow-core 作为 subtree（或一次性 vendor）
2. 迁移文档到 `docs/devflow/` 并修正相对链接
3. 迁移 skills 到 `skills/`，移除机密文件
4. 更新 `docs/README.md` 与 `AGENTS.md`
5. 验证链接与模板可用性（手动检查）

### 8.2 同步流程
- subtree 方案：通过 `git subtree pull` 同步 devflow-core 更新
- vendor 方案：用脚本复制并记录版本号

## 9. 非功能目标

- 可追溯性：所有流程文档与模板落盘在仓库内
- 低冲突：不破坏现有 docs 目录结构
- 可维护：提供清晰的同步/更新路径

## 10. 安全与风险

- 风险：误提交 devflow-core 的 `.env` 或本地机密
- 规避：迁移时明确排除 `.env`，必要时提供 `.env.example`

## 11. 兼容与版本策略

- 与现有流程并行，逐步迁移，不强行替换旧流程
- 允许按需在 `docs/devflow/` 中新增 RedCode IM 的扩展说明

## 12. 回滚与迁移

- 回滚方式：移除 `docs/devflow/` 与 `skills/devflow-*`，回退 `AGENTS.md` 与 `docs/README.md`
- 不涉及数据库迁移

## 13. 影响范围

- 新增文件：`docs/devflow/**`、`skills/devflow-*`、`docs/specs/SPEC-000001.md`
- 修改文件：`AGENTS.md`、`docs/README.md`（按方案落地时）
