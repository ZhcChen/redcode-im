# 全模块功能分析与测试重建设计

**日期**: 2026-03-01

## 1. 目标与范围

本轮工作目标：

1. 按主线模块完成功能盘点：`backend`、`admin`、`frontend`、`desktop`、`website`。
2. 在现有“最小测试骨架”基础上，从 0 重建测试体系（单元/集成/端到端/验收）。
3. 建立外部依赖本地模拟层，保证在无真实第三方资源时可稳定回归。
4. 采用“按模块分批”推进，每批独立完成：功能分析 -> 测试设计 -> 自动化测试 -> 验收。

## 2. 100% 口径（执行定义）

“100% 测试和验收”在本项目执行定义为：

1. **需求覆盖 100%**：每个功能点都有至少 1 条自动化测试用例映射。
2. **验收覆盖 100%**：每个功能点都有至少 1 条可执行验收场景（Given/When/Then）。
3. **通过率 100%**：当前批次测试与验收用例执行结果全部通过。
4. **可追溯 100%**：功能点 <-> 测试用例 <-> 验收场景三向可追踪。

说明：代码语句覆盖率会持续统计并提升，但不作为“100%”唯一判定口径，避免出现“高覆盖低有效性”。

## 3. 模块功能域

### 3.1 Backend

- 认证：注册/密码登录/SMS 登录/OAuth 登录/刷新/管理员登录。
- 用户：资料、密码、头像上传与下载链接。
- 好友：申请、处理、备注、删除、发起单聊。
- 房间/群：创建、入退群、成员管理、群设置、群头像。
- 消息：发送、加密消息、转发、编辑删除、已读、反应、搜索、附件上传。
- 举报反馈：举报、反馈、附件。
- 版本更新：客户端版本、热更新、下载链接。
- 管理后台 API：用户/角色权限/文件/日志/聊天记录/存储配置/Push 配置。
- 系统能力：WebSocket、Redis 会话与指标、后台清理任务。

### 3.2 Admin

- 登录与鉴权。
- 仪表盘（系统统计、存储统计、监控数据）。
- 用户管理、反馈、举报、聊天记录管理。
- 系统日志、Push 日志、文件审核任务管理。
- 系统设置（验证码、协议、应用名、上传策略、Push、存储、IP 地理配置）。
- 版本管理（安装包与热更新）。

### 3.3 Frontend（Flutter）

- 启动与登录链路（含版本检查与热更新入口）。
- 首页壳与会话/联系人/设置导航。
- 私聊与群聊核心链路。
- 联系人与好友申请。
- 设置与反馈、隐私协议、贴纸管理。
- Push 初始化与通知导航。

### 3.4 Desktop（Vue + Tauri）

- 登录、主导航、聊天、联系人、设置。
- 文件下载目录、版本检查更新。
- 协议文档页面与多账号状态保存。

### 3.5 Website（Nuxt）

- 落地页展示。
- 多平台下载入口。
- 动态版本查询与下载链接获取。

## 4. 外部依赖与本地模拟

基于当前代码，需模拟的外部依赖：

1. **Tencent COS**：对象上传、删除、存在性检查、下载链接、分片上传生命周期、CORS。
2. **Tencent CI（COS 内容审核）**：任务提交与查询。
3. **Google OAuth/JWKS（用于 OAuth 登录校验）**。
4. **Apple JWKS（用于 Apple 登录校验）**。
5. **Google OAuth Token + FCM Send（Push 发送链路）**。
6. **IPInfo（IP 地理位置解析）**。

模拟策略：

- 在 `tests/mocks/external` 提供统一 Mock 服务（Go 实现），通过环境变量切换到本地模拟地址。
- 对于当前硬编码第三方地址的代码，改为“可配置默认值”模式（默认线上地址，测试时注入 mock URL）。
- 测试环境中默认使用模拟服务，不依赖公网。

## 5. 分批执行顺序

### 批次 A（基础设施批）

- 落地外部模拟服务。
- 打通 backend 对 mock 的环境切换。
- 建立功能-测试-验收追踪矩阵模板。

### 批次 B（Backend 核心批）

- 覆盖认证、用户、好友、房间、消息、上传、版本、管理 API。
- Go 黑盒测试为主，Rust 单测补齐关键算法/策略。

### 批次 C（Admin 批）

- Admin 关键页面与 API 协议测试。
- Playwright 验收场景与后端契约联动。

### 批次 D（Frontend 批）

- Flutter 单元 + 集成 + 关键 E2E 场景。

### 批次 E（Desktop + Website 批）

- Desktop 关键交互链路。
- Website 下载链路与版本联动验收。

## 6. 交付物

每个批次必须产出：

1. 功能分析清单（模块级）。
2. 测试设计文档（测试类型、范围、优先级、边界与异常场景）。
3. 自动化测试代码。
4. 验收用例与执行结果。
5. 追踪矩阵更新（覆盖率与未覆盖项清零）。

## 7. 退出标准

全项目完成标准：

1. 五大模块功能点全部进入追踪矩阵。
2. 功能点测试覆盖率 100%。
3. 功能点验收覆盖率 100%。
4. 最新一次全量回归通过率 100%。
5. 所有外部依赖均可在本地 mock 环境下稳定回归。
