# Frontend 模块测试架构重建设计

**日期**: 2026-03-05
**范围**: `frontend`（Flutter）
**目标**: 在执行测试前先完成功能分析，建立完整的单元/集成/真机测试链路与验收口径。

## 1. 设计目标

1. Frontend 功能域 100% 纳入可追踪测试链路（功能 -> 测试用例 -> 验收结果）。
2. 测试分层明确：单元（纯逻辑）-> 集成（模块协作）-> 真机联调（真实网络与设备行为）。
3. 先补“高风险主链路”（启动/认证/聊天/联系人/设置/更新），再扩展边缘场景。
4. 测试结果必须可汇总输出，支持“已执行链路 + 通过率 + 风险项”一键回看。

## 2. Frontend 功能域拆解

### 2.1 启动与认证
- 启动初始化（版本检查、热更新入口、会话恢复）
- 登录（密码、短信）、登出、注销
- 鉴权总线与守卫跳转（`AuthStateBus` + `AuthGuard`）

### 2.2 首页壳与导航
- HomeShell Tab 导航（聊天/联系人/设置）
- 启动后 WebSocket 接入与未读角标

### 2.3 聊天主链路
- 会话列表加载与排序
- 聊天详情：文本/附件发送、引用/转发/置顶/反应
- 群聊扩展：群设置、管理员、禁言、群规则、群日志
- 搜索：本地 FTS + 服务端补充 + 跳转定位

### 2.4 联系人与社交
- 联系人列表
- 搜索用户与发起好友申请
- 申请处理后自动单聊兜底（ensure chat）

### 2.5 设置与发现
- 设置页：昵称、头像、退出、注销、清缓存/清记录
- 协议页与反馈页
- 发现页（当前为 mock 能力）

### 2.6 更新与外部依赖
- 整包更新（版本检查 + 下载链接 + 本地保存）
- 热更新（检查/下载/校验/应用/回滚）
- Push/通知、WebSocket、对象上传策略

## 3. 测试分层与覆盖策略

### 3.1 单元测试（L0）

关注纯逻辑与数据契约，不依赖真实网络/设备：

- 存储层：`TokenStorage`、`AppConfigStorage`、`AttachmentUrlCache`
- 服务层：`VersionService`、`AppConfigService`、`SettingsService` 的解析/错误映射
- 领域模型：`friend_models`、hot update models、消息模型序列化
- 关键规则：聊天室排序、订阅 LRU、搜索查询构造

**验收标准**
- 每个核心服务至少有“成功 + 异常 + 边界”三类断言。
- 单元测试全部通过后，才能进入集成层。

### 3.2 集成测试（L1）

关注模块协作（状态流、路由、副作用），尽量使用可控 mock/fake：

- 启动/认证状态流：未登录跳转、登录后状态广播
- 设置链路：保存/清理动作调用与 UI 反馈
- 聊天与联系人：关键状态变更后的 UI/缓存一致性
- 网络连通性检查：`healthz` 与 `WS` 握手

**验收标准**
- 每条集成链路至少包含 1 个主路径 + 1 个异常路径。
- 失败时给出可定位信息（页面断言、状态断言、日志断言）。

### 3.3 真机联调测试（L2）

关注真实设备行为与网络环境：

- 物理设备: `Pixel 8 Pro (3A091FDJG001DN)`
- 基础地址：`http://<LAN_IP>:8010` + `ws://<LAN_IP>:8010/ws`
- 执行项：启动 smoke、网络连通、登录/会话恢复、消息收发基础路径

**验收标准**
- 真机链路全部通过，且可复现执行命令。
- 失败项必须给出原因分类：环境/代码/外部依赖。

## 4. 本轮优先落地（先做高价值）

1. 新增高价值单元测试：
   - `TokenStorage`（会话读写、损坏数据回收）
   - `AppConfigService`（内存/存储/API 回退）
   - `VersionService`（query 拼装、解析、错误映射）
2. 复跑并校验 Frontend 全量单元测试。
3. 在真机跑 `integration_test/smoke_test.dart` 与 `integration_test/network_connectivity_test.dart`。
4. 更新矩阵与测试文档，输出“链路清单 + 执行结果汇总”。

## 5. 风险与约束

1. 设备联调依赖本机 LAN 与 Android 调试链路稳定。
2. 某些外部能力（Push、第三方 OAuth）在本轮先维持“链路可执行 + mock 可控”，不阻塞主流程。
3. Flutter 插件测试存在平台初始化差异，优先选择可稳定执行的断言。

2. Frontend 新增/重构测试代码。
3. 文档与矩阵更新（`docs/reference/testing/*`）。
4. 执行报告：列出本轮全部测试链路、命令、结果与后续风险。
