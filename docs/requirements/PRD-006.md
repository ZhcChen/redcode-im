# PRD-006: Backend Rust API 测试全覆盖计划

> 版本: 1.0
> 日期: 2026-01-22
> 状态: 待确认

## 1. 背景

当前 Backend Rust 测试覆盖 57/252 路由（22.6%）。本 PRD 规划将可测试路由覆盖率提升至接近 100%。

**排除范围**（依赖外部服务，跳过）：
- 存储服务相关：upload/signature/multipart/storage/avatar/attachment/download-url
- 外部服务相关：push/geolocation/captcha/test-*

**可测试路由：135 个**

## 2. 分阶段计划

### Phase 6: Rooms 模块完善（50 路由）

覆盖 `/rooms/{}/...` 下的所有非存储依赖路由。

| 子模块 | 路由数 | 示例 |
|--------|--------|------|
| 房间基础 | 8 | GET/PATCH/DELETE /rooms/{}, detail, settings |
| 成员管理 | 8 | members, admins, join, leave, transfer |
| 消息操作 | 12 | messages, pin, reactions, read, forward |
| 邀请/申请 | 6 | invitations, join-requests |
| 规则/禁言 | 8 | rules, mutes |
| 其他 | 8 | unread_count, notification-settings, operation-logs |

**预估测试用例：40-50 个**

### Phase 7: Admin 模块完善（53 路由）

覆盖 `/api/admin/...` 下的所有非存储依赖路由。

| 子模块 | 路由数 | 示例 |
|--------|--------|------|
| 用户管理 | 10 | users/{}, status, password/reset |
| 管理员账号 | 5 | admin-users, reset-admin-password |
| 角色权限 | 5 | roles, permissions/check |
| 设置管理 | 8 | privacy-policy, user-agreement, app-name, user-account-limit |
| Emoji 管理 | 8 | emoji-packs, emoji-items |
| 版本/热更新 | 10 | app-versions, hot-updates |
| 其他 | 7 | chat-history, logs/cleanup, metrics, nodes/monitor |

**预估测试用例：40-50 个**

### Phase 8: 其他模块补全（32 路由）

| 模块 | 路由数 | 说明 |
|------|--------|------|
| auth/* | 8 | admin/me, refresh, password/reset, sms, oauth |
| friends/* | 4 | delete, remark, chat, respond |
| users/* | 3 | 详情, heartbeat-logs, login-history |
| emoji-packs/* | 4 | suites, add, remove |
| versions/* | 4 | hot-update, download |
| activity/* | 2 | login, logout |
| e2ee/* | 2 | keys/bundle, key-bundles |
| 其他 | 5 | /, chats/{}, unread_counts |

**预估测试用例：25-30 个**

## 3. 验收标准

| 指标 | 当前 | 目标 |
|------|------|------|
| Rust 覆盖路由 | 57 | **190+** |
| Rust 测试用例 | 155 | **260+** |
| 覆盖率 | 22.6% | **75%+** |

## 4. 排除说明

以下路由因依赖外部服务而**不纳入本次测试**：

1. **存储相关**（约 40 路由）
   - */upload/*, */signature, */multipart/*
   - */avatar/*, */attachment/*
   - */download-url, */storage-providers/*

2. **推送相关**（约 10 路由）
   - /push/*, /api/admin/push/*

3. **地理位置/验证码**（约 5 路由）
   - */geolocation/*, */captcha

4. **WebSocket**（1 路由）
   - /ws

## 5. 执行顺序

```
Phase 6 (rooms) → Phase 7 (admin) → Phase 8 (其他)
```

每个 Phase 独立完成：PRD确认 → SPEC → 编码 → 测试 → 提交
