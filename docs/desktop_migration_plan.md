# Desktop 客户端迁移计划

## 1. 背景与目标
- 目标：将 `bear-chat-tauri` 中除 `.git` 外的全部代码与资源迁移到仓库现有的 `desktop` 目录，并与 `backend`、`frontend` 现有接口保持一致。
- 要求：完成迁移后，`desktop` 客户端统一复用当前后端 API，彻底移除 `bear-chat-tauri` 原有自建 API 与相关逻辑。
- 现状：仓库内 `desktop` 目录为空，无需准备回滚或双轨方案。

## 2. 范围界定
- 包含：代码迁移、依赖与构建脚本调整、配置与环境变量更新、客户端数据层重构、测试与交付流程更新。
- 不包含：新增业务功能、后端接口能力扩展、移动端 Flutter 应用改动。

## 3. 关键里程碑（负责人：AI 迁移负责人，优先即时完成）
1. **M0：迁移准备完成**：资料梳理、资源备份、开发环境确认。
2. **M1：代码资产迁移完成**：`bear-chat-tauri` 代码并入 `desktop`，完成基础编译。
3. **M2：API 对接完成**：数据访问层全量切换到 `backend` 现有接口，通过基础联调测试。
4. **M3：测试验收通过**：完成自动化与手动回归，出具测试报告。
5. **M4：发布准备确认**：发布所需产物就绪，支持材料同步。

## 4. 进度跟踪
- M0：已完成（2025-11-01）
- M1：进行中（桌面代码完成迁移与基础重构）
- M2：待启动
- M3：待启动
- M4：待启动

## 5. 阶段任务与交付物
### 阶段一：准备（负责人：AI 迁移负责人）
- 清点 `bear-chat-tauri` 代码结构、依赖、配置与自建 API 列表。
- 在 `desktop` 目录建立迁移分支，配置同步工具（若需保留历史，使用 `git subtree` 或 `rsync`，排除 `.git`）。
- 确认 `backend`、`frontend` 数据模型、鉴权流程、错误码规范，输出映射文档。
**交付物**：迁移计划执行清单、接口映射表、风险清单初稿。（状态：完成）

### 阶段二：资产迁移（负责人：AI 迁移负责人）
- 将 `bear-chat-tauri` 文件同步至 `desktop`，确保目录结构清晰，移除 `.git` 与无关生成物。（已完成）
- 调整 `package.json` / `pnpm` / `cargo` 等依赖文件（视项目技术栈而定），保持与现有工具链兼容。（已完成初版脚本）
- 根据后端逻辑重写桌面端页面、状态管理与联系人/消息核心流程。（进行中）
- 更新构建脚本与 CI 配置（如 `Dockerfile`、`build.sh`、`test_all.sh`）以适配新目录。（进行中）
**交付物**：可在本地编译运行的 `desktop` 客户端，依赖锁定文件。（状态：进行中）

### 阶段三：API 整合与数据层重构（负责人：AI 迁移负责人，与 Backend 协同）
- 分析 `bear-chat-tauri` 数据访问层，列出所有旧 API 调用并建立与 `backend` 对应接口的映射。
- 移除旧 API 模块、网络层封装与配置，保留必要的本地缓存或状态管理逻辑。
- 接入现有 `backend` API，包括鉴权流程、实时通信（若需）与错误处理；复用 `frontend` 中已有的请求封装与常量，确保行为一致。
- 验证 `desktop` 与后端的数据结构对齐，补充缺失的 DTO/模型转换。
**交付物**：新数据层实现、接口联调完成后的演示或录屏、更新后的技术文档。

### 阶段四：测试与质量保障（负责人：AI 迁移负责人）
- 由当前迁移团队编写并维护自动化测试，优先使用 `uv run python -m pytest` 完成 API/集成与桌面端 E2E 测试脚本。
- 执行手动回归，覆盖关键业务流程（登录、消息收发、文件传输等）。
- 监控性能指标与资源占用，确保迁移后无明显回归。
- 输出测试报告，列出问题与修复状态。
**交付物**：测试用例列表、测试报告、缺陷单闭环记录。

### 阶段五：发布准备（负责人：AI 迁移负责人，与 Release 协同）
- 制定发布步骤（构建、签名、分发渠道），并在预发环境完成灰度验证。
- 更新运维与支持文档，包含常见问题、日志定位路径。
**交付物**：发布记录、支持手册。

## 6. 资源与协同
- 人员：Desktop 开发 2 人、Backend 开发 1 人、QA 1 人、Release 1 人。
- 工具：版本控制（Git）、CI/CD、错误监控平台、性能监控工具。
- 协同：每周一次同步会议，里程碑前进行专门评审。

## 7. 风险与缓解措施
- **接口差异风险**：若 `backend` 缺少 `desktop` 需要的能力，提前在阶段三提出需求，必要时增加后端迭代。
- **历史代码兼容风险**：迁移过程中保留原仓库分支备份，使用特性开关逐步替换。
- **测试覆盖不足**：同步补充自动化测试，关键路径至少保证烟雾回归。
- **发布时间窗口受限**：与运营沟通窗口期，提前安排发布窗口。

## 8. 验收标准
- `desktop` 目录不再依赖旧 API，实现与 `backend` 一致的数据逻辑。
- 关键业务流程自动化测试通过率 100%，无阻塞级缺陷。
- 发布记录、技术文档、测试报告全部归档于 `docs` 目录。
- 项目负责人签字确认迁移完成并投入维护。
