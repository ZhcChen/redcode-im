# 朋友圈图片布局规范

本文定义朋友圈列表与动态详情的图片数量布局，作为 HTML 设计源和 Flutter 正式实现的共同基线。

## 1. 基本原则

- 单条动态最多展示 9 张图片，超出部分由发布流程阻止，不在内容流中截断表达。
- 图片顺序固定为从左到右、从上到下，不因横竖图比例改变顺序。
- 同一组图片使用统一方形缩略图裁切；正式图片采用 `cover`，焦点默认居中。
- 网格间距固定，组内不使用独立圆角；仅整个图片组裁切外圆角。
- 列表与详情使用相同的列数和行数规则，仅允许整体可用宽度不同。
- 没有图片时不渲染媒体容器，也不显示“无媒体”占位块。

## 2. 数量映射

| 图片数 | 列数 | 行数 | 整体比例 | 列表最大宽度 | 说明 |
| --- | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 1 | `4:3` | `240px` | 单图大预览；正式图片保持 `cover` 裁切 |
| 2 | 2 | 1 | `2:1` | `280px` | 两张等宽方图并排 |
| 3 | 3 | 1 | `3:1` | 内容区宽度 | 三张等宽方图单行展示 |
| 4 | 2 | 2 | `1:1` | `220px` | 标准 `2×2`，避免第四张形成孤立末行 |
| 5–6 | 3 | 2 | `3:2` | `282px` | 三列双行；5 张时末行左对齐 |
| 7–9 | 3 | 3 | `1:1` | `282px` | 标准九宫格；不足 9 张时末行左对齐 |
| 0 | 0 | 0 | 无 | 无 | 纯文字动态，正文后直接进入互动区 |

详情页不使用列表最大宽度限制，图片组可占满正文内容区；数量对应的比例、分栏与顺序保持不变。

## 3. 视觉与交互

- 网格间距：列表与详情分别为 `3px`、`4px`。
- 图片组圆角：列表 `10px`；详情使用 `--runtime-radius-surface`。
- 点击任意缩略图时，正式实现应打开图片浏览器，并以当前图片索引作为初始页。
- 图片浏览器支持左右切换、双指缩放、保存和返回；这些能力不改变内容流网格规则。
- 加载中、失败和受限图片应保持原网格尺寸，禁止因状态切换导致卡片高度跳动。

## 4. 演示数据

`assets/mock-data.js` 的朋友圈数据必须持续覆盖以下场景：

- `mom_1001`：3 张图
- `mom_1002`：9 张图
- `mom_1003`：1 张图
- `mom_1004`：4 张图
- `mom_1005`：6 张图
- `mom_1006`：纯文字
- `mom_1007`：2 张图

若后续修改 mock 数据，至少保留单图、双图、三图、四图、六图、九宫格和纯文字七种视觉回归样本，覆盖每一种唯一布局。

## 5. Flutter 映射

- 使用数量映射决定 `crossAxisCount`，不要根据图片自身宽高动态改变列数。
- 通过固定 `childAspectRatio: 1` 保证网格单元为方形。
- 5、7、8 张图片保持自然左对齐，不插入透明占位图片。
- 列表和详情复用同一个媒体网格组件，通过容器宽度和间距参数区分场景。
- 图片加载状态必须使用固定 `AspectRatio` 占位，避免滚动位置变化。
