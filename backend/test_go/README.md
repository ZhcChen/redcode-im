# Go 测试模块说明

本目录用于编写基于 Go 的后端流程验证。测试分为两类：

- **自动化测试**：使用 `go test` 执行，内部会调用 Gin 搭建的轻量级 Web UI 以及 HTTP 流程脚本，重点验证后端接口在典型业务路径下的表现。
- **手动测试**：使用 `go run .` 启动 Gin 服务，配合浏览器或其它前端工具进行可视化检查，适合临时调试或演示。

## 目录结构

- `main.go`：Gin 启动入口，提供基本健康检查，可按需扩展前端界面。
- `flow1_message_test.go`：流程 1 的自动化测试样例（短信登录 + 私聊消息收发验证）。
- 未来可根据流程扩展 `*_test.go` 或新增子目录，并保持注释清晰。

## 环境要求

1. 本仓库后端（Axum 服务）需运行在 `http://localhost:8010`，或通过环境变量 `TEST_GO_API_BASE` 指定其它地址。
2. PostgreSQL、Redis 等依赖需与后端服务一致。
3. Go 版本建议使用 `1.25.3`（当前同仓库配置）。

## 自动化测试

```bash
cd backend/test_go
GOCACHE=$(pwd)/.gocache GOMODCACHE=$(pwd)/.gomodcache \ 
  GOPROXY=direct GOINSECURE=* GOSUMDB=off \ 
  go test -v ./...
```

说明：
- 默认会向后端接口发送真实 HTTP 请求，请在本地或测试环境中运行，避免污染生产数据。
- 流程测试需要后端已启用通用验证码（当前约定为 `666666`），否则请先调整配置或修改测试常量。
- `-v` 选项可以输出流程结论，便于快速判断结果。

## 手动测试

```bash
cd backend/test_go
go run .
```

启动后访问 `http://localhost:8080/healthz` 验证服务是否就绪，可进一步扩展视图或 API 调用界面。

## 注释规范

- 测试代码必须编写详尽注释，重点描述**测试目的、前置条件、关键步骤及预期结果**。
- 注释建议兼顾读者背景（测试、后端、运维），必要时可标注接口路径、参数含义。
- 若流程复杂，可在文件头部先给出整体步骤，再在每个测试函数中逐段说明。
- 提交前请确保注释与实现保持一致，避免出现“注释与代码行为不符”的情况。
